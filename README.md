# TOKAMAK Remote Control v2

A responsive TOKAMAK web interface with two separate sections:

- **IoT Control** — live states, remote commands, acknowledgements and connection activity for the five configured devices.
- **TOKO AI** — dedicated assistant section and chat UI shell. Chat is deliberately marked inactive until the TOKO-to-MQTTY request/response adapter is installed and tested on TOKABOT.

## MQTTY configuration

- Browser broker: `wss://broker.mqtty.com:8884/mqtt`
- Telemetry: `tokamak-lab/demo/#`
- Command: `tokamak-lab/control/command`
- Command ACKs: `tokamak-lab/control/ack/+`
- Credential prefix: `tokamak-lab`

The dashboard does not contain a broker password. The user enters the generated MQTTY username/password in the UI. The password is held in page memory and cleared on disconnect; it is not stored in localStorage or included in this repository.

## Device command contract

QoS 1, retain false:

```json
{
  "request_id": "web-unique-id",
  "device": "round_lights",
  "state": "ON",
  "issued_at": 1795437000
}
```

`issued_at` is generated by the browser in Unix seconds. The dashboard updates a device to a confirmed state only after an ACK with `status: confirmed` and a valid `actual_state`.

## Deployment

Upload `index.html` and `README.md` to the root of the GitHub Pages repository, replacing the previous dashboard. The MQTT WebSocket connection needs HTTPS hosting for public access.

## TOKO integration status

The TOKO screen is a visual section only in this version. It does not publish chat requests yet. Implement and test the TOKO MQTT adapter on TOKABOT before enabling the chat composer. This avoids showing a fake working chatbot or sending messages to an unhandled topic.
